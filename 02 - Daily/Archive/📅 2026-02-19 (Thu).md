To link a log entry to a specific milestone, you need a "Key" that acts as a bridge. In database terms, this is your **Foreign Key**.

Since your milestones are currently items in a list within a Project note, rather than individual files, the best practice is to use **Block Links** or **Milestone IDs**.

---

### Option 1: The "ID" Method (Cleanest for App Logic)

Assign a simple ID (like M1, M2) to your milestones. In your log, you reference that ID.

**The Log Entry:**

> `22:00` :: Client requested rework on column logic. Project:: [[CRM App]] **Milestone:: M1** CycleType:: `#cycle/revert` Effort:: 4

**The Project Note:**

> - [ ] **M1**: Shuffle Columns | Due:: 2026-03-01 | Weight:: 10
>     

- **Why this works:** It is incredibly easy to write a Dataview query that says `WHERE Milestone = "M1"`.
    
- **App Transition:** In your Android app, your "Milestone" table will have a `milestone_code` column (M1, M2, etc.).
    

---

### Option 2: The "Block Link" Method (Obsidian Pro Way)

Obsidian allows you to link to a specific line (block) in another note.

1. In your Project note, add a "Block ID" to the milestone by typing `^m1` at the end of the line.
    
2. In your log, link directly to that block.
    

**The Project Note:**

> - [ ] **M1**: Shuffle Columns | Due:: 2026-03-01 | Weight:: 10 **^m1**
>     

**The Log Entry:**

> `22:00` :: Column rework. Project:: [[CRM App]] **Task:: [[CRM App#^m1]]** Effort:: 4

- **Why this works:** If you hover over the link in your log, you see the exact milestone text. If you change the name of the milestone, the link doesn't break.
    

---

### Option 3: The "Nested Object" (The Sabotage Tracker)

Since you want to prove "lack of prep" or "sabotage," you can link the **CycleType** directly to the **Milestone**.

> `22:00` :: Client meeting. **[Open:: [[CRM App#^m4]]]** (New AI Ask) and **[Revert:: [[CRM App#^m1]]]** (Scrapped Shuffle). Project:: [[CRM App]] Effort:: 4

---

### Best Practice Recommendation: "The Hybrid"

For someone moving toward app development, I recommend a combination of **Links** and **Keys**:

1. **Use a dedicated field** for the milestone link: `Milestone:: [[ProjectNote#^blockid]]`.
    
2. **Use a Task ID** in the display text so you can see it at a glance: `M1`.
    

#### How this looks in a DataviewJS "Progress Report":

Your script can now "crawl" your logs and group them by the Milestone link. It can then calculate the "Momentum" for each milestone specifically.

JavaScript

```
// Logic for your Project Note
let logs = dv.pages('"Logs"').where(p => p.Project?.path == dv.current().file.path);

// Grouping logs by Milestone
for (let group of logs.groupBy(p => p.Milestone)) {
    let milestoneName = group.key; // This is the link to the milestone
    let totalEffort = group.rows.Effort.array().reduce((a, b) => a + b, 0);
    
    dv.paragraph(`**${milestoneName}**: ${totalEffort} hours logged.`);
}
```

---

### Summary of Best Practices

- **Don't rely on text matching:** Don't just type "M1" in the log; use a link or a formal ID key so the "connection" is hard-coded.
    
- **Capture the "Why":** By linking a `#cycle/revert` specifically to a milestone, you create a paper trail that shows exactly which goals are being delayed by which changes.
