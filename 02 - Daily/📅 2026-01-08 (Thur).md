This DAX pattern is a **“switchboard” measure** that lets you **toggle which metric to display** based on a selection (usually from a slicer or the rows in a visual). It’s popular because it’s **maintainable**, **consistent**, and minimizes repeated logic.

Below I’ll break down how it works, why it’s used, what to watch out for, and a couple of ways to make it even more robust.

---

## What this measure is doing

### 1) Defining named “slots” with `VAR`s

Each `SC_01`–`SC_26` variable is essentially a **named alias** for the measure you want to show when that item is selected:

VAR SC_02_ _= [Engagement Favorability %]_

_VAR SC_03 = [Net Promoter Score #]

...

VAR SC_26 = BLANK()

Why VARs?

- Keeps the **switch list clean** (you reference `SC_03` rather than repeating the full measure).
- Makes it **easy to substitute or tweak** one metric in a single place.
- Useful if you later need to wrap/normalize values (e.g., divide by 1,000, format, apply filters).

> Note: `SC_01 = 0` looks like a **placeholder** — likely because Turnover % isn’t implemented yet.

### 2) Reading the “selector” via `SELECTEDVALUE`

SELECTEDVALUE('Scorecard Display'[Normalized Captions])

This grabs the **current caption** (e.g., `"Net Promoter Score"`) from the **disconnected scorecard table** used in a slicer or as a row header in a matrix. If there’s exactly one selection in context, you get that text; if there are multiple captions or none, `SELECTEDVALUE` returns BLANK (unless a default is provided).

### 3) Routing with `SWITCH`

RETURN

SWITCH(

    SELECTEDVALUE('Scorecard Display'[Normalized Captions]),

    "Net Promoter Score", SC_03,

    ...

    "# Google Ratings", SC

This is the **mapping**: when the selected caption equals `"Net Promoter Score"`, return `SC_03`; when it equals `"Average Case Fee"`, return `SC_12`, etc. So yes — **based on the row or slicer choice, it shows the appropriate measure**.

---

## Why teams use this technique

- **Maintainability:** To add a new metric, you only add a `VAR` and a line in `SWITCH`. To change a metric’s source measure, you update **one place**.
- **Consistent formatting & logic:** You can normalize all measures (e.g., units, filters, handling blanks) in one measure.
- **Cleaner visuals:** Instead of separate visuals per KPI, a single visual can **toggle** the metric shown.
- **Performance:** `SWITCH` evaluates the matched branch; combined with measure branching, this is typically **efficient**. VARs also prevent repeated evaluation of the same expression inside the `SWITCH`.

---

## Subtleties and best practices

1. **Default / fallback**
    
    - As written, if `SELECTEDVALUE` is blank or doesn’t match any label, the measure returns **blank**.
    - Consider a default to avoid a blank chart:
        
        RETURN
        
        SWITCH(
        
          TRUE(),
        
          SELECTEDVALUE('Scorecard Display'[Normalized Captions]) = "Net Promoter Score", SC_03__,_
        
          _-- more cases…_
        
          _TRUE(), SC_03   -- default
        
        )
        
2. **Exact text matching**
    
    - The keys (`"Net Promoter Score"`, etc.) must **exactly match** the values in `'Scorecard Display'[Normalized Captions]`.
    - If captions change (extra spaces, casing), your mapping breaks. A safer approach is to map on a **stable key/ID** (e.g., an integer) and display the caption separately.
3. **Data types & formatting**
    
    - Some branches return **%**, others **currency**, others **counts**. The displayed metric will use the **format of the measure you return**, not the wrapper measure. That’s good, but be consistent.
    - If you need uniform formatting or conversions (e.g., all to %, or thousands), wrap the VARs (e.g., divide, format, etc.).
4. **Context sensitivity**
    
    - Each referenced measure still respects the **current filter context** (date, location, etc.). If you need the scorecard to have its **own filter behavior**, apply filters inside those referenced measures or in the VARs.
5. **Disconnected table**
    
    - This pattern assumes `'Scorecard Display'` is a **disconnected table** used for selection, not joined to your fact tables. That’s standard and ensures clean switching.
6. **Versioned measures**
    
    - Measures like `...(Scorecard Version)` suggest **alternate logic** tailored for the scorecard (e.g., time frames, filters). This is common: the switchboard picks the “scorecard-approved” version rather than the general version.

## A more robust rewrite (keys + default)

If your display table has a numeric key (e.g., `'Scorecard Display'[Metric Id]`), you can avoid fragile text matching:

Scorecard Values =

VAR selId = SELECTEDVALUE('Scorecard Display'[Metric Id])

VAR SC_01_ _= 0_

_VAR SC_02 = [Engagement Favorability %]

VAR SC_03_ _= [Net Promoter Score #]_

_-- … other SC vars_

_VAR SC_26 = BLANK()

  

RETURN

SWITCH(

    TRUE(),

    selId = 1, SC_01__,_

    _selId = 2, SC_02,

    selId = 3, SC_03__,_

    _-- …_

    _selId = 26, SC_26,

    TRUE(), SC_03   -- default to NPS if nothing is selected

)

Using `SWITCH(TRUE())` lets you write **boolean conditions** and place a **final default** cleanly.

---

## How to add a new metric cleanly

1. Add it to your **Scorecard Display** table (key + caption).
2. Create/confirm the **source measure** (e.g., `[New KPI %]`), ensure the right formatting.
3. Add a new `VAR` in the switchboard measure and a corresponding case in `SWITCH`.
4. (Optional) If you’re standardizing units, wrap it (e.g., divide by 1,000, round).
5. Test by selecting the new item in the slicer/matrix.

---

## Potential improvements

- **Calculation Groups** (Tabular Editor): For large scorecards, a calculation group can centralize the selection logic and reduce measure sprawl. Your current pattern is perfectly fine; calc groups are a next step for advanced model governance.
- **Metadata table**: Store scale/format hints (e.g., `IsPercent`, `DisplayUnits`) in the scorecard table and use them to **normalize display**.
- **COALESCE for blanks**: If a metric can be blank, you can show a fallback:
    
    RETURN COALESCE(
    
        SWITCH( ... ),
    
        0
    
    )
