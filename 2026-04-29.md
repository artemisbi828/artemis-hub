Good intuition about Administrator being a policy constraint. Let me break this down:

## What is PATH?

Think of PATH like a **phone book for commands**:

```
You type: uv --version

PowerShell searches:
  ├─ C:\Windows\System32\  (is uv here?)
  ├─ C:\Program Files\     (is uv here?)
  ├─ C:\Users\...\bin\     (is uv here? ← YES, found it!)
  └─ ... more folders ...
```

PATH is a list of folders. PowerShell looks in each one, in order, until it finds a match.

## What is a terminal session?

Each time you open PowerShell, it's a **brand-new phone call**. It starts fresh:

```
Terminal 1 (open now)
  ├─ Gets default PATH from Windows
  └─ Does NOT have uv in PATH

  User types: uv --version
  PowerShell: "Not found, command not recognized"

(Close Terminal 1)

Terminal 2 (new window)
  ├─ Gets default PATH from Windows again
  └─ Does NOT have uv in PATH (because the old terminal is gone)
  
  User types: uv --version
  PowerShell: "Not found again"
```

Each terminal is **isolated** — changes inside one don't automatically appear in a new one.

## The three ways to give PATH knowledge about uv

### Option 1: Temporary (this terminal only, then dies)

```powershell
$env:Path = "C:\Users\jonas-adam.pascua\.local\bin;$env:Path"
```

This adds uv to **this specific terminal's** in-memory PATH. When you close the window, it's gone forever.

Think: "Tell this phone call about where to find uv" → hang up → next call has no memory of it.

---

### Option 2: Permanent (all future terminals, requires admin)

```powershell
# Run as Administrator
[System.Environment]::SetEnvironmentVariable(
  'Path',
  "C:\Users\jonas-adam.pascua\.local\bin;$([System.Environment]::GetEnvironmentVariable('Path', 'User'))",
  'User'
)
```

This writes to **Windows registry** (the system's database). Every new terminal reads this registry.

Why admin? Because the registry is a **system resource** — only elevated users can modify it. Think: "Store this phone book in the building's shared directory" (needs building manager permission).

After this runs, all new terminals automatically know about uv:

```
Terminal 1: uv --version ✅ works
(close)
Terminal 2: uv --version ✅ works (reads updated registry)
(close)
Terminal 3: uv --version ✅ works (reads updated registry)
```

---

### Option 3: Per-session in a file (advanced, skip for now)

You can also add PATH changes to PowerShell's startup script (`$PROFILE`), but that's overkill for now.

---

## Why you're hitting this issue

1. You installed uv to bin
2. Windows doesn't know about that folder by default
3. Each new terminal has no memory of where uv is
4. You have to tell it manually (Option 1, temporary) or change Windows' registry (Option 2, permanent + admin)

---

## Recommended next move

Do **Option 2 once** (permanent):

1. Open PowerShell as Administrator
2. Paste the full `[System.Environment]::SetEnvironmentVariable(...)` command
3. Close all PowerShell windows
4. Open a new PowerShell normally
5. Type `uv --version` — it should work without any setup

From then on, every new terminal will find uv automatically. No more `$env:Path = ...` needed.
